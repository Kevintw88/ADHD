# 評估發現排序手冊

## 步驟

1. 呼叫 `assessment-reports.list_findings`（預設 min_severity=medium）。清單已依確定性規則排序：
   嚴重度、評估點數、對應 ATT&CK 技術是否出現在實際攻擊路徑上。
2. 排序以工具結果為準。你可以補充說明，但不可改變順序；若認為順序不合理，在「需人工確認」列出理由。
3. 對前 5 項說明風險、影響範圍、修補方式與修補前檢查。

## 常見修補前檢查

| 修補 | 先確認 |
| --- | --- |
| 強制 LDAP Signing / Channel Binding | DC 的 2889 事件，找出仍用未簽章 LDAP 的主機與設備 |
| 停用 NTLM / NTLMv1 | 先開 NTLM 稽核模式，觀察產線與 EDA 環境相依 |
| 停用 SMBv1 | 舊設備、量測機台、印表機是否仍依賴 |
| 移除服務帳號的 Domain Admins | 服務實際需要的最小權限，改用 gMSA |
| 修正 AD CS 範本 | 範本目前的使用者與用途，先加主管核准再移除自填主體 |
| 啟用 LAPS | 本機管理員帳號的使用流程與緊急存取 |

## 回覆格式

- 結論：最需要先處理的 3 項與理由
- 清單：優先分數、代號、說明、修補方式、修補前檢查
- 需人工確認：業務相依、變更窗口
